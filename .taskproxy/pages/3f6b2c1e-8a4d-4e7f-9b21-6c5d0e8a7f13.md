### What it does

<webui-page-segment>

Task Proxy can write commit messages, code reviews, page parts, and scripts, and suggest how imported markdown files become pages. Every draft lands where you can change it first. Set it up in **Settings**, on the **AI** tab: on **Providers**, choose **Add Provider** and what you want to use, and follow the steps it shows; then turn on what to use AI for, choose default models, and write instructions. Each provider's models are listed together wherever a model is chosen.

</webui-page-segment>

### Claude through a subscription (Claude Code)

<webui-page-segment>

A Claude subscription has no API key, but Claude Code uses its sign-in. Choose **Claude Code, with a Claude subscription**, check the models to use (Sonnet, Opus, Haiku), and whether it may look at other files in the project. It never changes files or runs commands from Task Proxy. Claude Code is a command-line tool, apart from the Claude app. Run installs it with the installer for this computer: Windows, macOS, or any Linux, including Arch-based ones such as Garuda. It puts `claude` in `~/.local/bin`, which Task Proxy finds even when it isn't on your PATH:

```pwsh
if ($IsWindows) { irm https://claude.ai/install.ps1 | iex } else { bash -c 'curl -fsSL https://claude.ai/install.sh | bash' }
& ((Get-Command claude -ErrorAction SilentlyContinue).Source ?? (Join-Path $HOME '.local' 'bin' 'claude')) --version
```

Sign in once: run this, answer what Claude Code asks in the Terminal Manager, sign in with your Claude account in the browser it opens, then type `/exit`.

```pwsh
$env:PATH += [IO.Path]::PathSeparator + (Join-Path $HOME '.local' 'bin')
claude
```

Then check it answers:

```pwsh
'Reply with only: ready' | & ((Get-Command claude -ErrorAction SilentlyContinue).Source ?? (Join-Path $HOME '.local' 'bin' 'claude')) -p --setting-sources user --strict-mcp-config --model haiku
```

Claude Code runs in the project's folder, where a project's own Claude settings could change what it does, so Task Proxy asks you to trust a project before Claude Code works in it, as it does before running a page's script.

Task Proxy also has it read only your own Claude settings, never the project's. With **Look at the project** on, Claude Code can read any file in the project, a `.env` file or a key kept there included, and what it reads is sent to Anthropic, so choose No for a project with secrets in its files. Task Proxy's own variables and secrets are never sent. Each draft counts toward the subscription's usage, like any Claude Code prompt.

</webui-page-segment>

### Codex, GitHub Copilot, Cursor, and Qwen Code

<webui-page-segment>

These use a subscription you already have, as Claude Code does: **Codex** with a ChatGPT plan, **GitHub Copilot** with a Copilot plan, **Cursor** with a Cursor plan, and **Qwen Code** with a Qwen account. Choose one, and its steps install the tool and start its sign-in in the Terminal Manager. Then check the models to use: each starts with that tool's main models, and you can add any other it offers. Task Proxy writes the command itself, so that the tool can read the project but never change it:

- **Codex** runs in its read-only sandbox, without your own Codex settings.
- **GitHub Copilot** may only use its tools that read, never asks a question, and leaves out the repo's custom instructions.
- **Cursor** runs in Ask mode. Cursor takes the request as an argument, and Windows passes at most about 32,000 characters that way, so on Windows its models start limited to 28,000 characters.
- **Qwen Code** runs in plan mode, which can't change files or run commands.

Each can read any file in the project, and what it reads is sent to its company, so the same care applies as for Claude Code with **Look at the project** on. Each runs in the project's folder, so Task Proxy asks you to trust the project first. Check a tool is installed and signed in:

```pwsh
foreach ($Tool in 'codex', 'copilot', 'agent', 'qwen') {
    $Found = Get-Command $Tool -ErrorAction SilentlyContinue
    "{0,-8} {1}" -f $Tool, ($Found ? $Found.Source : 'not installed')
}
if (Get-Command codex -ErrorAction SilentlyContinue) { codex login status }
```

Not offered, and why:

- **Gemini CLI:** Google moved its subscriptions to Antigravity CLI in June 2026.
- **Antigravity CLI:** run without a person there, it changes files and runs commands by default, and can only be stopped by changing your own Antigravity settings. Use a **Google Gemini API key**, which has a free tier.
- **Aider:** it has no subscription sign-in and writes files into the project.
- **opencode:** how it runs without a person there isn't documented.

</webui-page-segment>

### Ollama on this computer

<webui-page-segment>

Free and private: everything stays on this computer. Install Ollama from ollama.com and pull a model, then add a provider and choose **Ollama**. Save, and its models are listed. Ollama on another computer is set with **Running on**, and its address.

```pwsh
$Model = 'qwen2.5-coder:7b'
ollama pull $Model
ollama list
```

</webui-page-segment>

### LM Studio, API keys, and other servers

<webui-page-segment>

- **LM Studio:** start its server in its Developer tab, then choose **LM Studio**.
- **An API key:** OpenAI, Anthropic, Google Gemini, Mistral, xAI (Grok), DeepSeek, Groq, Cerebras, Together AI, Fireworks AI, or OpenRouter. Choose it, and paste a key from its site (the step's button opens it). Gemini, Mistral, Groq, and Cerebras have free tiers to try them. Its models are listed once saved.
- **Others** that speak the OpenAI chat API, such as vLLM or a server at work: **Another OpenAI-compatible server**, with its address ending in `/v1`, and a key if it needs one.
- **Any other tool:** **Another command**, run in PowerShell with the request on its input, with a row for each model.

Keys are kept by Task Proxy on this computer, encrypted, and are never shown again. **Test** sends a short prompt to the provider's first model.

</webui-page-segment>

### Your company's cloud: Azure, AWS Bedrock, and Vertex AI

<webui-page-segment>

- **Azure OpenAI or Azure AI Foundry:** paste the endpoint and a key from the resource's **Keys and Endpoint** page, and add each deployment by its name, since Azure's models are the ones your company deployed.
- **AWS Bedrock:** create a Bedrock API key in the AWS console's **Amazon Bedrock** page, under **API keys**, and type its region, such as `us-east-1`. A short-term key lasts up to 12 hours and works only in its region; a long-term key lasts until the date you choose. Save, and the models and inference profiles your account can call there are listed. Newer models such as Claude are called through an inference profile, whose id starts with its geography, as in `us.anthropic.claude-sonnet-5`.
- **Google Vertex AI:** install the Google Cloud CLI, sign in once, and type your project ID and location (`global` unless your company keeps its data in one region). Gemini models start with `google/`, and Claude models with `claude-`, which must be turned on in Model Garden first. There is no key: Task Proxy gets a new access token from your gcloud sign-in each hour.

```pwsh
gcloud auth login
gcloud auth print-access-token | Out-Null; if ($?) { 'Signed in to Google Cloud.' }
```

</webui-page-segment>

### Instructions

<webui-page-segment>

Every request first tells the model it is helping in Task Proxy, and how a project's `.taskproxy` folder is laid out: pages in `pages/*.md`, the navigation in `Navigation.json`, variable names in `Variables.json`, and scripts in `scripts/*.ps1`, and that a page's `pwsh` blocks get a Run button. Settings shows this on the **Shared** tab as built in. Requests then get the built-in instructions for that use, then your shared instructions, then the ones for that use. For each, a project's own instructions are used in place of the global ones when it has any, like a project's Git token; a project with none uses the global ones. A useful start for Git commit messages:

```text
A first line summarizing the change, then one line per change, each starting with Feature: or Bug:. No other text.
```

</webui-page-segment>
