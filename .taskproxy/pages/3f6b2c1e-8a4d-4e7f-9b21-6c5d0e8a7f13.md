### What it does

<webui-page-segment>

Task Proxy can write commit messages, code reviews, page parts, and scripts, and suggest how imported markdown files become pages. Every draft lands where you can change it first. Set it up in **Settings**, on the **AI** tab: on **Providers**, choose **Add Provider** and what you want to use, and follow the steps it shows; then turn on what to use AI for, choose default models, and write instructions. Each provider's models are listed together wherever a model is chosen.

</webui-page-segment>

### Claude through a subscription (Claude Code)

<webui-page-segment>

A Claude subscription has no API key, but Claude Code uses its sign-in. Choose **Claude Code, with a Claude subscription**, check the models to use (Sonnet, Opus, Haiku), and whether it may look at other files in the project. It never changes files or runs commands from Task Proxy. Claude Code is a command-line tool, apart from the Claude app. Run installs it with the installer for this computer: Windows, macOS, or any Linux, including Arch-based ones such as Garuda. It puts `claude` in `~/.local/bin`, which Task Proxy finds even when it isn't on your PATH:

```pwsh
if ($IsWindows) { irm https://claude.ai/install.ps1 | iex } else { bash -c 'curl -fsSL https://claude.ai/install.sh | bash' }
& ((Get-Command claude -ErrorAction SilentlyContinue).Source ?? (Join-Path $HOME '.local' 'bin' 'claude')) --version
```

Sign in once: run this, answer what Claude Code asks in the Terminal Manager, sign in with your Claude account in the browser it opens, then type `/exit`.

```pwsh
$env:PATH += [IO.Path]::PathSeparator + (Join-Path $HOME '.local' 'bin')
claude
```

Then check it answers:

```pwsh
'Reply with only: ready' | & ((Get-Command claude -ErrorAction SilentlyContinue).Source ?? (Join-Path $HOME '.local' 'bin' 'claude')) -p --model haiku
```

Each draft counts toward the subscription's usage, like any Claude Code prompt.

</webui-page-segment>

### Ollama on this computer

<webui-page-segment>

Free and private: everything stays on this computer. Install Ollama from ollama.com and pull a model, then add a provider and choose **Ollama**. Save, and its models are listed. Ollama on another computer is set with **Running on**, and its address.

```pwsh
$Model = 'qwen2.5-coder:7b'
ollama pull $Model
ollama list
```

</webui-page-segment>

### LM Studio, OpenAI, and other servers

<webui-page-segment>

- **LM Studio:** start its server in its Developer tab, then choose **LM Studio**.
- **OpenAI, Anthropic, or OpenRouter:** choose it, and paste a key from its site (the step's button opens it).
- **Others** that speak the OpenAI chat API, such as Groq or vLLM: **Another OpenAI-compatible server**, with its address ending in `/v1`, and a key if it needs one.
- **Any other tool:** **Another command**, run in PowerShell with the request on its input, with a row for each model.

Keys are kept by Task Proxy on this computer, encrypted, and are never shown again. **Test** sends a short prompt to the provider's first model.

</webui-page-segment>

### Instructions

<webui-page-segment>

Every request first tells the model it is helping in Task Proxy, and how a project's `.taskproxy` folder is laid out: pages in `pages/*.md`, the navigation in `Navigation.json`, variable names in `Variables.json`, and scripts in `scripts/*.ps1`, and that a page's `pwsh` blocks get a Run button. Settings shows this on the **Shared** tab as built in. Requests then get the built-in instructions for that use, then your shared instructions, then the ones for that use. For each, a project's own instructions are used in place of the global ones when it has any, like a project's Git token; a project with none uses the global ones. A useful start for Git commit messages:

```text
A first line summarizing the change, then one line per change, each starting with Feature: or Bug:. No other text.
```

</webui-page-segment>
