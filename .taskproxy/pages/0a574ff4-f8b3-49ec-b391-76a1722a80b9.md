### Run Project

<webui-page-segment>

Use `cargo tauri dev` to build and run the Tauri app being developed.

```terminal
cargo tauri dev
```

</webui-page-segment>

### Run with a local MyFiCDN

<webui-page-segment>

While MyFiCDN's local server is running, `cargo tauri dev` loads Web UI from it instead of cdn.myfi.ws, so CDN changes show in the app before they are deployed. Start the server from the MyFiCDN checkout beside this one, then start or reload the app (Ctrl+R) to pick up CDN changes. The terminal running `cargo tauri dev` says which it uses each build.

```pwsh
Set-Location ../../Websites/MyFiCDN
./PowerShell/RunLocal.ps1
```

To keep cdn.myfi.ws while the local server runs:

```pwsh
$env:TASKPROXY_CDN = 'live'
cargo tauri dev
```

</webui-page-segment>

### Testing

<webui-page-segment>

Backend tests are Rust tests. 

Run `trunk build` once first on a new checkout, because the tests embed `dist/`.

```pwsh
trunk build
```

Run Backend Tests

```pwsh
cargo test -p taskproxy
```

UI tests use [Playwright](https://playwright.dev) and need no running app, since they serve the frontend straight from the repo and stand in for the backend. They do load the shared Web UI components from cdn.myfi.ws, so they need network access.

```pwsh
npm install
```

On Linux the tests use `/usr/bin/chromium` if it exists, so the second command can be skipped. 

```pwsh
npx playwright install chromium
```

Run every test: the unit tests (Vitest, in a simulated browser), then the browser tests (Playwright). Both test the minified files the app loads, so minify first

```pwsh
npm test
```

Run only the unit tests, which are most of them

```pwsh
npm run test:unit
```

Watch the unit tests, running the ones a change affects

```pwsh
npx vitest
```

Run only the browser tests: layout, drag and drop, the mouse, media, the terminal, and the end-to-end flows

```pwsh
npm run test:browser
```

Open the interactive runner for the browser tests, with watch mode and a timeline for each test

```pwsh
npm run test:ui
```

Open the last browser test report, with a screenshot and trace for each failure

```pwsh
npm run test:report
```

Run one unit test file, or one browser test file

```pwsh
npx vitest run tests/unit/components/git-manager.test.mjs
npx playwright test tests/browser/components/git-manager.spec.mjs
```

Run tests by name

```pwsh
npx vitest run -t "commit"
npx playwright test -g "commit"
```

### Stress tests

Once a week, for each project worked on that week, run the tests the week's changes affect many times each under heavy load. A test that fails here only some of the time is a timing race to fix. This never runs as part of a normal test run, Publish, or CI. With nothing changed in the last 7 days it says so and runs nothing.

```pwsh
pwsh ./PowerShell/StressTests.ps1
```

Stress every test, whatever changed

```pwsh
pwsh ./PowerShell/StressTests.ps1 -All
```

Look back further, or run each test more or fewer times

```pwsh
pwsh ./PowerShell/StressTests.ps1 -Days 14 -Repeat 5
```
